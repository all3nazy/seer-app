# سِير | SEER

منصة عربية لتشغيل المدارس الأهلية والحضانات. يعتمد المشروع على Next.js 15 وTypeScript وSupabase Auth وPostgreSQL. المساعد التشغيلي حتمي ويعمل دون اشتراك ذكاء اصطناعي مدفوع.

هذا الفرع يعالج [طلب التنفيذ رقم 1](https://github.com/all3nazy/seer-app/issues/1). تتبع حالة التحقق والقيود في [سجل التنفيذ](docs/implementation-status.md)، وحدود النظام في [المعمارية](docs/architecture.md).

## التشغيل محليًا

يلزم إصدار Node.js مطابقًا لـ `engines` في `package.json`: إصدار 22.12 أو أحدث من السلسلة 22، أو السلسلة 24، أو 26 فأحدث، مع npm. استخدم الإصدارات المثبتة في `package-lock.json`:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

أضف عنوان مشروع Supabase ومفتاحه العام إلى `.env.local`:

| المتغير | الاستخدام |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | عنوان مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المفتاح العام المتوافق مع إعداد المشروع؛ يطبّق RLS صلاحيات السجلات |
| `SEER_SUPPORT_WHATSAPP` | اختياري؛ رقم الدعم الدولي بأرقام فقط، دون `+` أو مسافات |

لا تضع مفتاح `service_role` في متغير يبدأ بـ `NEXT_PUBLIC_`، ولا تحفظ كلمات مرور أو أسرار في المستودع. غياب إعداد Supabase يمنع فتح المسارات المحمية. غياب رقم الدعم يعرض حالة «قيد الإعداد» دون رقم افتراضي.

## قاعدة البيانات

لا تعِد تشغيل `supabase/migrations/0001_core.sql` على مشروع قائم. المشروع الحي يحتوي بالفعل على الجداول الأساسية وقيود إضافية لا تظهر في ملف البداية.

- لقاعدة جديدة ومعزولة: طبّق الترحيلات حسب ترتيب أسماء الملفات، بدءًا من `0001_core.sql`.
- لقاعدة SEER القائمة: قارن المخطط والسياسات والقيود وسجل الترحيلات أولًا، ثم طبّق الترحيلات الجديدة التي تمت مراجعتها فقط. لا تستخدم أمر دفع جماعي مع سجل ترحيلات فارغ دون تسوية خط البداية.
- ترحيل `reconcile_tenant_boundaries` ينقل مساعد العضوية إلى مخطط `private` ويوحّد المفاتيح الأجنبية المركبة لمنع ربط سجلات منشآت مختلفة. يتحقق من البيانات القائمة؛ فشل التحقق يوقف المعاملة بدل حذف البيانات.
- ترحيل `school_operations` يضيف سياسات الكتابة حسب الدور وسجل التدقيق وإجراء التهيئة المقيد. لا يعاد تطبيقه بعد نجاحه.

راجع [خطة الترحيل والتراجع](docs/implementation-status.md#خطة-الترحيل-والتراجع) قبل أي تغيير حي.

## الحساب الأول والصلاحيات

إنشاء المنشآت والعضويات ليس متاحًا للعامة. يستخدم المشغّل المخوّل `scripts/onboard-admin.ts` لدعوة المدير، ثم تهيئة المنشأة بعد تحقق البريد. السكربت محصور بعنوان قاعدة SEER ويرفض تهيئة مستخدم لديه عضوية قائمة لتجنب التكرار.

1. طبّق ترحيل العمليات المراجع أولًا، وتأكد من نشر صفحة `/auth/setup` في النسخة المقصودة.
2. في إعدادات Supabase Auth، اضبط `Site URL` إلى `https://seer-app-psi.vercel.app` وأضف `https://seer-app-psi.vercel.app/auth/setup` إلى عناوين إعادة التوجيه المسموحة. تحقق من إعداد إرسال البريد.
3. حمّل المتغيرات التالية من مخزن أسرار موثوق في بيئة المشغّل فقط. لا تعرض قيمها في الطرفية أو سجل CI، ولا تضفها إلى ملف منشور أو متغير عام:

| متغير المشغّل | الاستخدام |
| --- | --- |
| `SUPABASE_URL` | يجب أن يكون عنوان مشروع SEER: `https://vhcdzonkgalpcozbhmmj.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح خدمة SEER من القناة الموثوقة؛ لا يستخدمه المتصفح ولا يبدأ بـ `NEXT_PUBLIC_` |
| `SEER_APP_ORIGIN` | `https://seer-app-psi.vercel.app` |

4. أرسل دعوة إلى البريد الذي حدده المالك، باستبدال البريد التوضيحي في الأمر التالي:

```bash
npx --no-install tsx scripts/onboard-admin.ts invite 'admin@example.com'
```

5. يفتح المستلم رابط الدعوة من بريده ويعيّن كلمة مرور من 12 حرفًا على الأقل مع تأكيدها في `/auth/setup`. لا ترسل كلمة المرور إلى المشغّل. إنشاء الحساب وحده لا يمنح الوصول إلى منشأة.
6. بعد تحقق البريد، نفّذ التهيئة. حدد المالك الاسم «سير تجريبي» والنوع حضانة (`nursery`)؛ المثال يستخدم هذين الاختيارين. الأنواع المتاحة عمومًا: `school` أو `nursery` أو `kindergarten`:

```bash
npx --no-install tsx scripts/onboard-admin.ts provision 'admin@example.com' 'سير تجريبي' nursery
```

تستدعي التهيئة `bootstrap_organization` لإنشاء المنشأة وعضوية `owner` وحدث التدقيق في معاملة واحدة. تتطلب الدالة مستخدمًا موثق البريد، والتنفيذ متاح لـ `service_role` فقط. لا تكرر التهيئة بعد نجاحها، ولا تمنح مفتاح الخدمة للمستخدم. لم تُرسل دعوة ولم يُنشأ حساب أو منشأة ضمن الفحص المسجل حتى الآن؛ يظل ذلك خطوة تشغيلية بعد تجهيز الاعتمادات والتحقق من البريد.

المستخدمون ذوو الدور `owner` أو `admin` يديرون سجلات منشأتهم. يستطيع `staff` قراءة السجلات التشغيلية المسموحة؛ قراءة الفواتير وسجل التدقيق مقيدة بالمديرين. لا يكفي تغيير معرّف المنشأة في المتصفح للحصول على صلاحية.

## الفحوص

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

تحتاج اختبارات المتصفح إلى Chromium الخاص بـ Playwright؛ ثبّته وفق بيئة التشغيل قبل تنفيذها. الفحص المحلي أو نجاح بناء Vercel وحده لا يثبت نجاح تسجيل الدخول أو عزل المنشآت في الإنتاج. يسجل [سجل التنفيذ](docs/implementation-status.md) ما نُفّذ فعلًا وما بقي.

## نطاق إدارة العمليات

تتيح الواجهة إنشاء وتعديل الفروع والأطفال وأولياء الأمور والتسجيل والفواتير، وتعديل اسم المنشأة ونوعها للمديرين. تختار سجلًا من القائمة لتعديله؛ لا تدخل معرّفه يدويًا. التصفح 25 سجلًا في الصفحة، وقوائم اختيار السجلات المرتبطة محدودة بأول 500 اسم، مع الاحتفاظ بالربط الحالي عند تحرير سجل خارج هذه القائمة. لا تتضمن هذه النسخة حذف السجلات أو إدارة العضويات أو واجهة ربط الطفل بولي أمره.

## المساعد والدعم

المساعد يفسر نوايا عربية محددة وأسئلة المتابعة السياقية، ويستعلم وفق عضوية المستخدم وسياسات قاعدة البيانات. تعرض المحادثة السؤال والجواب في تبادلات مستقلة؛ يحتفظ بآخر 30 تبادلًا في ذاكرة الصفحة فقط، وتمسح عند تبديل المنشأة أو بدء محادثة جديدة أو إعادة التحميل. لا يعتمد على نموذج مدفوع ولا يدعي إتمام تغيير في البيانات بمجرد المحادثة. التعديلات تمر عبر نماذج العمليات وصلاحيات الخادم وتأكيد المستخدم.

رابط واتساب يجهز رسالة دعم عامة فقط. لا يضم أسماء المنشآت أو الأطفال أو أولياء الأمور أو وصف مشكلة حرًا. لا يرسل المشروع رسائل واتساب تلقائية ولا ينفذ مدفوعات.

تستخدم [الأدوار العشرون](docs/agent-team.md) للمراجعة والتنفيذ. لا توجد علاقة توظيف أو تمثيل لـ Apple أو Asana أو Slack.


سجل الإنتاج سُوّي بعد فحص الكتالوج: `0001/core` اعتماد للمخطط الموجود دون إعادة تنفيذه، ثم الترحيلان `20261106122846` و`20261106123009` مطبّقان. راجع أحدث متابعة في [سجل التنفيذ](docs/implementation-status.md) قبل أي ترحيل لاحق؛ لا تعِد تطبيق الملفات يدويًا.
